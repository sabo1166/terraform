Deployment Process

Terraform Execution Flow

STEP 1: Parse & Validate

HCL files parsed → Syntax validated → Logic checked

STEP 2: Plan (Dry Run)

Preview all changes → Show what will be created/modified/deleted → Safe to review

STEP 3: Human Review

Developer approves plan → Ensures intention is correct → Catches mistakes

STEP 4: Apply

Provider plugin calls cloud APIs → Resources created in AWS/Azure/GCP

STEP 5: Track

State file updated → Maps code to resource IDs → Stores attributes

✓ Critical Best Practice: Always run terraform plan before terraform apply. This single step catches 99% of mistakes before they hit production.

Risk Mitigation

Common Mistakes & Solutions

❌ Committing .tfstate to Git

File contains passwords, API keys, database credentials

→

✓ Remote S3 Backend

Encrypted, versioned, backed up, audit logged

❌ Team conflicts on state

Two engineers apply simultaneously → Corruption

→

✓ DynamoDB Locking

Only one apply at a time → State stays clean

❌ No terraform plan review

Apply changes without previewing → Disasters

→

✓ Always Plan First

Review → Approve → Apply → Catches 99% mistakes
